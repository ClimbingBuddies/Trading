### Non-blocking advice

The existing scaffold grants `anon` and `authenticated` broad table privileges on all four opinion tables, including `TRUNCATE`, while RLS has no policies. RLS does not make `TRUNCATE` a safe client boundary. This does **not** fail RES-001 because the task is to define the role and non-double-counting contract, and `external-opinion-v1` explicitly reserves operational access design for RES-002. Before RES-002 is called operational, revoke unnecessary client privileges and establish deliberate grants/RLS for the actual collection/read boundary.

Also retain the specification's recommendation to add machine-verifiable lineage from Market Assessment evidence to the canonical opinion/source identity where practical; the current URL/text matching rule is sufficient as a RES-001 contract but should not remain the only enforcement mechanism after operationalisation.

### Decision

**PASS WITH ADVICE.** Every material RES-001 Definition-of-Done requirement is independently verified. The current scaffold's access grants are an implementation concern for RES-002, not a failure of the RES-001 review contract.
