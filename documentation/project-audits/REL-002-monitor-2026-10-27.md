## Reproduced defects

Before this change, `describePipelineStatus` could display `Morning review completed` with `warning=false` for a `COMPLETE` response whose counts were **0/4 researched, 0 published and 0 evaluated**. It checked nonnegative numbers but not the claimed completion's consistency.

An unknown state such as `toString` also resolved through the label object's prototype and returned a function as the title. Separately, the component checked only the root version/incidents array before storing a response; malformed nested problems/instruments could reach `.map()` or `.some()` and crash the expanded panel. A failed refresh retained previously successful status data in the detailed panel.

These were reproduced with isolated inputs. The real service was **not** observed falsely claiming COMPLETE; the live checkpoint below correctly reported ATTENTION. This is client-side defence against incomplete/contradictory responses, not a claim that the database has been repaired or that an incident exposed private data.

## Changes

- Added one typed validator covering every collection/date/flag/count used by the monitor panel. Invalid payloads and read failures clear the previous status, rather than rendering malformed or cached successful evidence.
- Stage counters must be safe nonnegative integers and cannot progress beyond their prerequisite counts. Due-market completion needs positive supported coverage and fully researched/published/evaluated counts, recorded completion/controller evidence, available research, valid calendar trust and no current blockers/unsupported instruments.
- A non-session skip still needs trusted calendar evidence. Missing calendar trust cannot become a successful holiday skip. Trust that expires between polls stops being treated as current.
- Current problems and unresolved older incidents remain warnings. Unknown/prototype-like state strings produce a safe unknown-status label.
- Before-deadline PENDING work remains pending. After the deadline, a still-pending snapshot is explicitly **completion unverified**, not proof that the controller failed. Existing monitor age and clock-skew guards remain in place.

This validates the display contract and obvious consistency, not the truth of every backend count. Full backend receipt, scheduling and calculation verification is still required by the active plan. No stage was completed, retried, configured or fabricated by this code.
