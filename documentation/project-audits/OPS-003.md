# OPS-003 — Standardise Market AI independence metadata

## Independent audit — 18/Aug/2026 15:02 Australia/Perth

**Starting project-plan status:** `IN REVIEW`  
**Decision:** **PASS WITH ADVICE**

### Definition of Done

> New rows record a version such as `independent-market-ai-v1` and `technical_engine_input_used = false`.

| Check | Verdict | Evidence |
|---|---|---|
| Canonical Market specification requires the independent methodology version | VERIFIED | `automation/daily-market-assessment.md` explicitly requires `methodology_version = 'independent-market-ai-v1'` for every new or updated assessment produced under the specification. |
| Canonical Market specification requires Technical Engine independence metadata | VERIFIED | The same specification explicitly requires `technical_engine_input_used = false` and prohibits use of `technical_indicators`, `market_scores` and `market_convergence_assessments` as analytical inputs. |
| Live table supplies the standard methodology version for new rows | VERIFIED | Live `public.gpt_market_assessments.methodology_version` has default `'independent-market-ai-v1'`. |
| Live table supplies `technical_engine_input_used = false` for new rows | VERIFIED | Live `public.gpt_market_assessments.technical_engine_input_used` has default `false`. |
| Live database prevents a new/updated assessment from asserting Technical Engine input was used | VERIFIED | Live constraint `gpt_market_assessments_no_technical_engine_input` is `CHECK (technical_engine_input_used IS NOT TRUE) NOT VALID`. In PostgreSQL, a `NOT VALID` check is still enforced for subsequent inserts/updates while historical rows need not be validated. This preserves legacy `NULL` rows but prevents `true` on new/changed records. |
| Existing history remains distinguishable from the new standard | VERIFIED | Live data currently contains 30 legacy 01/Aug/2026 rows with both fields `NULL` and 30 14/Aug/2026 rows with methodology `market-assessment-real-data-v1` and `technical_engine_input_used = false`; historical records were not falsely relabelled as having used the new methodology. |
| Production Market Scheduled Task is aligned to the canonical specification | VERIFIED | Fresh task state shows the Daily Trading Market Assessment prompt retrieves `automation/daily-market-assessment.md` fresh and explicitly repeats the independence boundaries. |

### Decision rationale

**PASS WITH ADVICE.** The Definition of Done is satisfied at the persistence contract and execution-specification layers: future rows produced normally by the canonical workflow are standardised to `independent-market-ai-v1` and `false`, while the database additionally prevents `technical_engine_input_used = true` on subsequent writes.

There has not yet been a completed production assessment row written under `independent-market-ai-v1`. That is expected because the subsequent project gates are responsible for activation and first unattended-run verification. `OPS-005` should explicitly confirm that the first real scheduled run persists the exact metadata values on all newly created assessment rows.

### Non-blocking advice

1. During `OPS-005`, verify every newly persisted assessment row for the unattended run has `methodology_version = 'independent-market-ai-v1'` and `technical_engine_input_used = false`.
2. The Daily Trading Market Assessment is already enabled in current task state even though `OPS-004` is still `PLANNED`. Treat `OPS-004` as an explicit verification/reconciliation gate rather than assuming activation work remains to be performed.
3. The `NOT VALID` independence check is appropriate for retaining legacy unknown rows, but a later data-quality/security review may decide whether the constraint should eventually be validated after legacy rows are deliberately classified.
