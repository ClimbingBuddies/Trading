## Advice

1. Supabase's managed grant hook currently gives `anon` and `authenticated` both `USAGE` on `net` and `EXECUTE` on `net.http_post`. No application-owned wrapper exposes arbitrary requests, and no pg_net member is in `public`, so this does not invalidate the acceptance. Still, verify that `net` remains outside PostgREST's exposed schema list whenever API exposure settings or extension grants change.
2. Two pg_net responses in the independently inspected two-hour window reached the live five-second timeout. In both cases, the invoked Edge Function continued and wrote a successful `sync_run`; later calls returned HTTP 200. Consider setting an explicit timeout above the observed loader duration, or documenting the difference between pg_net response timeout and loader completion, so monitoring does not misclassify successful long-running loads.

These are non-blocking improvements. Neither is required to satisfy SEC-004's exact Definition of Done.
