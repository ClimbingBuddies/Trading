### Check 3 — Required Vercel Production variables are effective

**VERIFIED by live behaviour.** The current fallback-free code throws when either required variable is absent. Fresh production requests to data-backed routes succeed and return real Supabase-backed content, which independently proves the production deployment has usable values for both required variables rather than relying on removed source fallbacks.

### Check 4 — Frontend does not require a privileged Supabase credential

**VERIFIED.** Current `lib/supabase.ts` creates the browser/server-rendered public client from the project URL and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` only. It does not read or require `SUPABASE_SERVICE_ROLE_KEY`, Twelve Data credentials, or another privileged backend secret.

The `NEXT_PUBLIC_` naming also makes the intended public-client boundary explicit; therefore only the publishable Supabase key is appropriate in that variable.
