## Source snapshot

`technical_engine.asx_source_snapshot_v1(instrument_id uuid, cutoff_at timestamptz)` is a private, SECURITY INVOKER, read-only function returning JSON. It returns `status` (`ready` or `blocked`), a plain machine `reason`, `cutoff_at`, and for ready inputs: `anchor_audit_id`, `terminal_audit_id`, `window_start`, `window_end`, ordered `audit_ids`, ordered `observations` with canonical stored row values, and `source_hash`. The hash covers ordered audit status/times/relevant metadata and complete selected source values/provenance, excluding only the caller cutoff when comparing unchanged source state. It is a consistency fingerprint, not a cryptographic authorization token.

Only active ASX equity instruments in AUD and an active Yahoo provider qualify. Provider-symbol identity must match the canonical `.AX` symbol exactly. Session dates are stored at midnight UTC as labels and must match raw payload dates; do not reinterpret them as exchange trading instants. Exclude the current Sydney date and later dates. Provider presence and weekdays do not certify exchange-session completeness.

Find a successful, clean, demonstrable full-window audit anchor (at least 300 calendar days requested, up to the latest completed Sydney date). Verify actual full fetch attempts for history-window v1 audits; legacy full-fetch audits require their reviewed metadata and returned counts. Never treat inherited `correction.state=resolved` as proof of a full fetch. Follow each newer overlap audit's `previous_audit_id` strictly back to that anchor. Require terminal success, ordered timestamps, exact identity and no missing/intervening/forked/cyclic lineage. Any unresolved correction, failed/running audit, rejected bar in any attempt, conflicting response, or preserved-close/unresolved-gap state blocks the input. A new revision needs a new clean full anchor. Old stored rows do not clear quarantine.

Use only the verified anchor horizon, clipped to the most recent calendar year ending at the latest accepted request end. Require every chosen row to match one admitted audit's provenance, canonical typed values and embedded raw bar. The existing database stores prices as `numeric(20,8)` and volume as `numeric(24,4)`: compare native payloads at exactly those PostgreSQL decimal scales, while independently rejecting invalid native values. This is defined storage normalization, not a floating-point tolerance. Reject ambiguous or invalid rows, nonfinite prices, nonpositive adjusted close, impossible OHLC, and negative/nonfinite volume; null volume is allowed. No raw-close substitution. Keep rows outside the verified horizon unused. The absence of a calendar certificate or an arbitrary older provider revision remains explicitly unknown.

### Complete bars alongside close-null placeholders

Normalizer version 2 retains `history_window_version=1` and the existing SQL admission contract. Within a single provider response and Sydney session, it may select a whole complete bar when every other bar is either exactly identical or has both close and adjusted close null with exactly matching open/high/low/volume. Volume must be present and finite for this exception. The selected bar must pass normal OHLC validation. No fields are combined; one-null-only cases and any native numeric disagreement remain quarantined, including differences smaller than storage precision. Both original bars, timestamps, selection reason and selected timestamp remain in `duplicate_bars`.

The first daily v2 job after a legacy rejected audit performs a bounded one-year full fetch to establish a new clean anchor. It must return every previously rejected session within that horizon; omission/rejection prevents writes and leaves `normalization_revalidation.state=unresolved`. Unchanged unresolved recovery does not repeat full fetches and requires reviewed recovery. Transport/write failures remain pending for the existing bounded job retry policy. A completed clean revalidation returns to ordinary overlap fetching. Existing audits and snapshots are preserved. Full-range requests and successful jobs alone do not prove calendar completeness or research eligibility.

## Calculation and score integration

New identities are `technical-engine-asx-v1` and `technical-score-asx-v1`. Use the existing deterministic indicator formulas and score weights, with daily periods from the admitted snapshot and completed ISO weeks of Sydney session dates. A rolling one-year source window cannot provide weekly SMA200; preserve that limitation as unavailable/partial. Do not splice older price generations to obtain it.

All indicators and the score must come from one snapshot, fixed cutoff and refresh batch. Match the existing indicator storage boundary (`numeric(24,8)`) before scoring; MACD signal metadata retains native precision. Pin source prices and volume to the same snapshot; do not reread mutable observations by ID or combine prior indicator batches. Verify the source fingerprint again before publication. Currentness checks must compare source fingerprints and the completed Sydney week, not only observation IDs or calculation dates. This does not fence later concurrent ingestion or certify market freshness. The private `technical_engine.asx_input_snapshots` table retains each exact source/cutoff envelope; equal source hashes at different cutoffs are distinct snapshots so weekly calculations can be reproduced. Existing snapshots are insert/read only for the service role. Preserve previous methodology rows/history.

Use the existing Technical scheduler and execution lock if the calculation release passes acceptance. Preserve Tiingo behavior and report ASX versions, counts and blockers separately. Failures must be durable and retries must not mistake Tiingo-only success for ASX completion. No additional recurring job is authorized by this contract. Convergence, shared outcomes and benchmark/calendar enablement are a separate reviewed milestone; an ASX Technical score alone does not enable them.

`asx_calculate_v1(jsonb)` computes from the admitted in-memory snapshot. `refresh_asx_v1(uuid)` persists that exact source/cutoff envelope, its indicators and score with one batch ID. `asx_score_source_matches_v1(bigint)` checks current persisted-source consistency and the completed Sydney-week boundary; it is not a market-session freshness certificate. All functions are private SECURITY INVOKER and executable only by the trusted service role/owner. The read-only source function itself sees one consistent database snapshot; the volatile refresh makes a second source call before publishing. Later concurrent ingestion can invalidate a score, so downstream admission must call the source-match check at use, alongside its own freshness/session checks.

The existing `run_v1` runner retains Tiingo counts in its existing columns and adds ASX counts/versions/blocker categories under `metadata.asx`. `metadata.pipeline_contract=tiingo-v1+asx-v1` identifies composite successes; an earlier Tiingo-only success does not suppress the first composite attempt. An ASX source blocker marks the composite receipt failed with `asx_source_blocked`, retaining useful completed Tiingo/ASX work. A raised calculation exception rolls back both stages in the existing exception block and retains the failed run receipt. The three-attempt retry limit, advisory lock and cron identities/cadences are unchanged.
